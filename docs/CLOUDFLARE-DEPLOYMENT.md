# Cloudflare Workers deployment

This repository is configured to deploy Online Technical Help to Cloudflare Workers with static assets and the same-origin form API.

## Production host

- Canonical origin: `https://onlinetechnicalhelp.com`
- Custom domains in `wrangler.jsonc`: apex and `www`
- Worker name: `online-technical-help`
- Static assets: `public/`
- Worker entry: `src/cloudflare-worker.js`

Cloudflare Custom Domains create the DNS record and TLS certificate during deployment when the zone is in the same Cloudflare account and no conflicting hostname record exists.

## Git deployment

In Cloudflare, import the GitHub repository `Zynette/HamiltonTechHelp` as a Worker and name the Worker `online-technical-help` so it matches `wrangler.jsonc`. Use `main` as the production branch. The default deploy command `npx wrangler deploy` is sufficient; this project has no frontend build step.

The repository remains private. Grant the Cloudflare Workers & Pages GitHub app access only to this repository if possible.

## Required form configuration

The website itself can deploy without a form provider, but form submissions remain disabled until the Worker has a valid `FORMSPREE_FORM_ID` environment variable.

Set `FORMSPREE_FORM_ID` in the Worker settings after creating and verifying the Formspree form that delivers to `techspecialistsupport@gmail.com`. Do not commit account credentials or tokens.

Until that variable is configured, the form endpoint returns a clear message directing customers to email the support address instead of pretending a request was sent.

## Verification after deploy

Check:

1. `/` loads over HTTPS at the apex domain.
2. `/healthz` returns `{"status":"ok"}`.
3. `/robots.txt` points to the production sitemap and Workers preview URLs remain noindex.
4. `/sitemap.xml` contains the canonical apex URL.
5. The apex page contains the canonical URL, Open Graph URL and JSON-LD generated by the Worker.
6. After Formspree is configured, submit one owner-authorized test for each form type and verify delivery in the receiving inbox.
7. Confirm both apex and `www` resolve with valid TLS.

## Architecture note

The existing Node server remains the local/test implementation. Cloudflare uses a Worker adapter that reuses `src/validation.js`, applies the same origin, payload-size and validation controls, uses Cloudflare's connecting-IP header for the local abuse counter, injects production metadata into the homepage, and serves the remaining public files through Workers Static Assets.
